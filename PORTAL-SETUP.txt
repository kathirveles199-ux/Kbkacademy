KBK ACADEMY PORTAL INTEGRATION — TEST BEFORE PUBLISHING

Files in this package:
- index.html: existing homepage, Login / Portal button added in header and hero CTA.
- login.html: Supabase email/password sign-in and role-based routing.
- student-dashboard.html: assigned lessons and private recording playback.
- mentor-dashboard.html: mentor-only batch and lesson overview (read-only first version).
- dashboard.html: compatibility route for onboarding redirect.

- admin.html: uploaded admin file preserved unchanged.
- student-test.html: original test page preserved; do not link it publicly.

DEPLOY STEPS
1. Back up your existing repo folder or download the current GitHub repo ZIP.
2. Copy the HTML files from this package into the repository root, replacing index.html and onboarding.html only after checking the preview. Add the new login/dashboard files. Keep any additional files already in your repository.
3. Commit and push to GitHub Pages.
4. In Supabase Dashboard > Authentication > URL Configuration, ensure Site URL is https://kathirveles199-ux.github.io and add redirect URL https://kathirveles199-ux.github.io/Kbkacademy/** (and the exact login.html URL if wildcard patterns are not accepted).
5. Test using separate student, mentor and admin accounts. Do not share passwords or signed recording URLs.

IMPORTANT LIMITATIONS
- Browser code uses the Supabase publishable key; never put service_role/secret keys in HTML.
- Student and mentor dashboards rely on existing Supabase RLS policies. Test each role with a real session.
- The mentor page is intentionally read-only for batch/lesson tables because the uploaded code does not establish every database column and write policy needed for safe creation/upload forms. Do not call this production-ready until end-to-end role tests pass.
- Existing admin.html is preserved from the uploaded file and may not yet have Supabase authentication/role guards; it must be protected before using it as an actual admin portal.
- Onboarding still stores the diagnostic locally in localStorage. Cross-device persistence to profiles/database is not implemented in this first integration.
